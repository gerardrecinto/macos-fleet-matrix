A macOS runner that lives for one job and then goes away.

This is a design and a working simulation of a control plane that gives each macOS CI job its own short-lived Apple Silicon runner. It is for platform and CI engineers.

How it works

Each build gets a clean machine, uses it once, and then it is thrown away.

1

Start from one image

Every runner boots from the same known-good macOS and Xcode image.

2

One lease, one job

A runner is leased to a single job for a set time. Only that job can release it.

3

Expired means quarantined

A runner past its lease is pulled out of use, not reused.

What is real today

The booking logic works. The real Mac machines and cloud setup are plans only.

Works and is tested

  • The lease code and CLI you just used.
  • A Swift probe for host heat and memory pressure. It checks that a Mac is not too hot or too full before it gets a job.
  • A Rust reaper that quarantines expired leases. It takes back machines whose time ran out.

Design only

  • Booting a real VM from this page. The CLI has an opt-in Tart backend (Tart runs macOS VMs on Apple Silicon), but it has only been tested against a fake tart script, never on a real VM.
  • Image builds and rollout. The Terraform and Kubernetes files pass CI but have never been applied to a live account or cluster. The setup scripts are written and checked, but never switched on. Kyverno is one of those checks, a rule list that blocks unsafe software on the cluster.

Run it locally

Needs Python 3.11 or later. State is saved between commands.

git clone https://github.com/gerardrecinto/macos-fleet-matrix
cd macos-fleet-matrix
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
pytest
mfm inventory sample
mfm lease acquire --runner m1-01 --job demo-123
mfm lease release --runner m1-01 \
  --job demo-123 --result success
mfm metrics

State lives in ~/.local/state/mfm/state.json. Delete it to start over.
