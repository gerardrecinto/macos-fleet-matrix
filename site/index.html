The idea

macOS CI capacity is expensive and stateful by default. Treat each runner as disposable.

1

Immutable image

Build a macOS and Xcode image once with Packer. Runners start from that known-good image every time.

2

One lease, one job

A runner is leased to exactly one job with a TTL. A release must name the same job, so a stale caller cannot free someone else's runner.

3

Fail closed

A lease past its expiry gets quarantined, not reused. The reaper that enforces this is a small Rust program in the repo.

Run it locally

Python 3.11 or later. Works on a laptop in simulation mode.

python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
pytest
mfm inventory sample
mfm lease acquire --runner m1-01 --job demo-123
mfm lease release --runner m1-01 \
  --job demo-123 --result success

Each CLI call starts from a fresh sample inventory, so state does not carry between commands. This page keeps one inventory alive so you can see transitions.

What this does not do
  • It does not boot a VM. No Tart adapter exists yet, so a lease changes a record, not a machine.
  • A draining runner has no way back to ready in the code today. Destroy and replenish are design, not implemented.
  • The multi-cloud and Kubernetes pieces pass validation but have never been applied to a live account or cluster.
